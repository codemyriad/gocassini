A fixes-only release for everyone on 0.4.0. Cassini comes back cleanly after a reboot or a nightly backup that stops the server, and agents can connect over MCP again behind AppAPI.

### Highlights

**A reboot no longer looks like a fresh install.** After a restart, installed transcription models stay ready, settings and a pinned GPU are kept, and the saved Talk test room is remembered. If Nextcloud is still starting or busy, Cassini keeps recording and checks again, instead of refusing recordings. The **New recordings can't be saved** notice clears by itself within about five minutes of Nextcloud answering.

**Agents connect over MCP again.** Behind Nextcloud AppAPI, agents no longer get an HTTP 403.

### Before you upgrade

- **On Nextcloud All-in-One**, turn off AIO's Talk Recording-server and set `NEXTCLOUD_KEEP_DISABLED_APPS=true`. Otherwise AIO removes Talk's recording backend every time Nextcloud starts, and Talk refuses Cassini after each restart or backup. The **Use Cassini as Talk's recording backend** panel now says so.
- **Hand edits to `settings.json` or `llm-settings.json` need a restart.** Cassini reads them once, at start. A new install creates `settings.json` on the first save in Settings.
- **Cassini no longer writes `app-state.json`.** An existing file can be deleted; backup scripts should treat it as optional.

### Improvements

- **Setup warnings:** the two warnings above the meeting list are now one-line strips. Administrators get a button to Operator › Doctor; everyone else can copy a link to send an administrator.
- **Support bundles** say whether Cassini's data is on storage that doesn't survive the container, and keep the start-up lines that explain a reset.
- **Saving is safer:** a leftover temporary file or a power cut right after a save no longer loses settings.
- The ExApp images opt out of ONNX Runtime telemetry.

### Fixes

- The recording setup warning no longer hides the bottom of the meeting list, including the **Prepare** button for people who aren't administrators.
- A settings file that can't be loaded is kept as `settings.json.rejected-N` instead of being overwritten, and the log says how to restore it. Until then, new recordings are shared only with the people who were in the call.
- Enabling the app in AppAPI no longer fails when the volume is full, and saving retention settings no longer reports an error for a change that was saved.

Every change is listed in the [developer changelog](https://github.com/codemyriad/gocassini/blob/main/CHANGELOG.md).
