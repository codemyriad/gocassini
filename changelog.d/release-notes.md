### Changed
- Each release now has notes written for the people who run Cassini, published on gocassini.com/changelog: what is new, what got better, and what to do before upgrading. The GitHub release shows them first, with every change folded underneath. The App Store's changelog shows them instead of the developer changelog. `prepare-release.sh` refuses a stable version until its notes are merged (`--no-user-notes` overrides). For a release cut on a release branch, `sync-release-changelog.sh` brings its published notes back to main, which puts them on the site. `scripts/user-release-notes.sh --sources` gathers what the next notes must cover. See `docs/release-notes.md`.
