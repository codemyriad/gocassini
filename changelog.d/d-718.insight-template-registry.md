### Added
- Insight templates is a real panel in the Operator: it lists every template this build ships, and each row opens onto the exact instruction that template sends to the model — the prompt itself, not a description of it — beside the id, version and content hash an insight document records. So a document you found a month later can be traced to the prompt that produced it, rather than to a name that may since have meant something else.
- A second template, "Commitments and owners": one section per person who spoke, with what they took on and when they said so, then what was assigned to somebody who never answered, then what nobody claimed. `cassini insight run --workflow todos` runs it, and every other workflow the panel lists can be named the same way.
- `cassini insight workflows` prints the same list on the command line, and `--json` adds each workflow's instruction verbatim. It is how you check what a given image will actually send, without reading its source. The Operator's templates panel is this command's output.

### Changed
- The publish pipeline's summary step and the `summarise` insight now run the same prompt file, not two copies of it. The summary is an insight like any other, so it names the template it runs; the bytes it sends are unchanged.
- A prompt whose bytes are not compiled into the image is not listed and cannot be named — a template you can select is a template that will run. Two of the templates drawn in the design have no prompt authored yet and are therefore absent rather than shown as unavailable.
- Editing a shipped prompt now fails the lint check until its version is bumped and its hash re-pinned. Prompt files are markdown, and a markdown-only change used to run no tests at all while changing what the product sends to a model.
