### Changed
- **Cassini works out who can see recordings from what is already there, instead of asking before it will record anything.** When an installation has no storage mode recorded, the answer is now read off the installation itself the moment the app is enabled. Recordings in the `Cassini` Team folder mean **Meeting participants**, kept exactly as they are. Recordings only in the service account's own folder, and a fresh installation with no recordings at all, mean **Everyone with a Nextcloud account**. Recordings in both places mean **Meeting participants**, and the ones in the other folder are reported as before, under `stranded_root` and `stranded_recordings`, rather than being moved. The one rule underneath all of it: Cassini never widens an existing archive on its own. Nothing is copied, moved or deleted by the resolution; the mode is recorded and the recordings stay where they are.
- **`GET /operator/storage` says when Cassini answered for you.** A mode resolved this way reports `mode_source: "resolved_on_enable"`, so the record shows plainly that nobody clicked, and what the installation looked like at that moment is in the container log beside it.
- **A mode that is already recorded is kept, and no longer questioned.** A mode an older version wrote on its own, or one an interrupted switch left behind, used to stop publishing and recording until an administrator confirmed the mode they already had. Confirming a fact is not a decision. `mode_confirmed` is true for every recorded mode now, and `awaiting_choice` is always false.
- **The `CASSINI_STORAGE_MODE` deploy option is unchanged** and still takes precedence: it is read before anything looks at the installation, and it is still honoured only where it fits.

### Fixed
- **Talk recordings are no longer refused because nobody had chosen a storage mode.** An installation that had not answered the setup question lost every recording made in the meantime, and the moderator saw only Talk's "The recording failed". Recording is refused only for a prerequisite that is genuinely missing, such as an absent `cassini` service account. Where Cassini cannot read the recordings it already has, for instance because Nextcloud stopped answering, it records no mode, says so on `GET /operator/status`, waits before publishing and looks again the next time the app is enabled. It still records.
