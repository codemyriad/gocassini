### Changed
- One person's imports no longer wait behind another person's whole queue. Each person's imports run one at a time, oldest first (a retried import keeps its place), and the server runs up to three imports at once across everyone. Administrators can change that number in Settings › Storage › Imports. It applies at once and is kept across redeploys; until it is set there, `CASSINI_MAX_CONCURRENT_IMPORTS` sets the starting value.
- The Import sheet now says whether an import is waiting for the server, queued behind the person's own earlier imports ("Queued · 2 imports ahead"), or being fetched, checked or added. A queued import shows no progress bar.
- Delivering a meeting to Nextcloud no longer writes a temporary second copy of it to the server's disk: the check that Nextcloud holds the right file now reads it back without saving it. An import also deletes its validation copy as soon as it has been checked, so it needs at most twice its size in free space.

### Fixed
- An import whose file stops downloading from Nextcloud Files, or arrives only a trickle at a time, now fails after two minutes so it can be retried, instead of waiting until someone cancels it.
- Every import now has a time limit that grows with the file's size (about four hours for the largest), so a stuck step can no longer hold up other imports indefinitely.
- Large imports no longer fail because uploading the meeting to Nextcloud took longer than two minutes.
- Imports can no longer fill the server's disk. An import starts only if the disk can hold it while keeping 5 GiB free for recordings. Otherwise it waits for running imports to finish. If it could not fit even then, it holds up no other imports, and it fails once nothing else is importing or after half a minute of not fitting, telling the person the file is too big and to contact their administrator. The server log records the sizes involved.
- An import cancelled, or interrupted by a restart, just as it finished is now shown as done and is searchable, since the meeting is already in Nextcloud. Before, it showed as cancelled, or imported again after the restart.
- An import retried after its upload had already reached Nextcloud now checks Nextcloud's copy and makes the meeting's tags and marks searchable, as a first attempt does.
- An import can no longer be cancelled once its meeting has been added and shared, while it is being made searchable. A cancel there used to show Cancelled for a meeting that was then added anyway.
