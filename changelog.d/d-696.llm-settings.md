### Added
- A Settings surface in the app, beside Browse and Operator (admins only). It hosts transcription quality — moved off the operator page — and the new LLM settings: endpoints, whether summaries run and on which endpoint and model (with a fetched model list). Each endpoint carries its own request bounds — timeout and response-token limit — with empty fields meaning the defaults (900s / 4096).
- The app keeps its own LLM settings (`llm-settings.json` beside the job database; `GET`/`PUT /settings/llm`): named endpoints, and the summary policy. Switching between a hosted provider and a self-hosted model server is one settings change, with no ExApp redeploy. `GET /settings/llm/providers/{id}/models` lists what an endpoint serves. API keys are stored server-side and never returned.

### Changed
- `LLM_BASE_URL`, `OPENROUTER_API_KEY` and `LLM_MODEL` in the deploy environment now only pre-fill the LLM settings on the app's first start; after that the stored settings are what every build receives.
