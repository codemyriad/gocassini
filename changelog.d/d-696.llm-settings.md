### Added
- A Settings surface in the app, beside Browse and Operator (admins only). It hosts transcription quality — moved off the operator page — and the new LLM settings: endpoints, whether cleanup and summary run and on which endpoint and model (with a fetched model list), and request bounds.
- The app keeps its own LLM settings (`llm-settings.json` beside the job database; `GET`/`PUT /settings/llm`): named endpoints, and for each of transcript cleanup and meeting summary whether it runs, on which endpoint, with which model. Switching between a hosted provider and a self-hosted model server is one settings change, with no ExApp redeploy. `GET /settings/llm/providers/{id}/models` lists what an endpoint serves. API keys are stored server-side and never returned.
- The recorder accepts a separate endpoint per step: `READABLE_BASE_URL` / `READABLE_API_KEY` / `READABLE_MODEL` and `SUMMARY_BASE_URL` / `SUMMARY_API_KEY` alongside the existing `SUMMARY_MODEL`.

### Changed
- `LLM_BASE_URL`, `OPENROUTER_API_KEY` and `LLM_MODEL` in the deploy environment now only pre-fill the LLM settings on the app's first start; after that the stored settings are what every build receives. Existing installs keep their current behaviour.
