### Added

- Talk recordings now record exactly when they started. The meeting file gains `meeting.recordedAtUtc` (mirrored as the `CASSINI_RECORDED_AT_UTC` tag), its `DATE` tag holds that start instead of the time the file was built, and `catalog.json`, the meeting list, search hits, the rooms list and MCP results carry `recordedAtUtc`. `dateLabel` is unchanged for older clients.
- `cassini retag --recorded-at-utc <RFC 3339 UTC>` adds the recording start to an existing file without changing its meeting id.
- `cassini inspect` prints a meeting's `recorded_at` fields and a `meeting_start` line, and warns when `CASSINI_RECORDED_AT_UTC` disagrees with the manifest. `inspect --meeting-times` and `meetings context` add `meetingStart` (`source`, `value`): `recordedAtUtc`, else a `DATE` tag with an offset that is not the build time, else the `recordedAtLocal` label.

### Changed

- Meeting times are shown in your local time zone: the viewer's meeting list, meeting header, search, insight names and exported transcripts, and the CLI's `list`, `rooms`, `search`, `meetings context` and `inspect --meeting-times`. Sorting, month headings and date filters follow the time shown. Meetings that carry only the older date label are shown as before.
- Past ExApp recordings are corrected on upgrade in the meeting list: the ExApp works out each one's start from what it kept (the recording's own timeline, then the recorder's start, then the job) and adds it there. Imported and cron-era meetings are left as they are.
- Writing that start into the delivered `.opus` files themselves is up to the administrator: Operator › Doctor › Recording times in past recordings shows how many recordings need it and runs it when asked (once it has finished counting them), with Pause and Resume. Before anything is written it says what a rewrite does in this Nextcloud, read from its capabilities: each file gets a new version (if versioning is on, the earlier one stays in the service account's data, outside its quota, until Nextcloud expires it), and, if the Activity app is on, everyone the meeting is shared with gets a "file changed" entry, which by Nextcloud's defaults is neither emailed nor notified; people who turned those on get a notification per recording, and email in their usual activity digest. Shares, marks and file ids are kept, and pausing never leaves a file half-written: one whose upload was sent is finished, one not yet uploaded is left as it was. It runs at about one file every 30 seconds per worker (two workers); a file that cannot be rewritten (missing, or a CLI too old) is listed with the reason and retried from the same button. `/operator/status` reports the same as `recorded_at_migration`; `POST /operator/migrations/recorded-at/start` and `/pause` are the admin routes behind the buttons.
- `cassini meetings list --from/--to` are read in your local time zone. `published/meetings-list` and the MCP `list` tool accept `from`/`to` as an instant with its offset (`2026-08-11T14:30:05+02:00`); dates without a zone match what they matched before, and a meeting known only by its date label is compared against the bound's own digits, as the CLI always did.
- The viewer and the static exporters date a file with no `meeting.recordedAtUtc` by its `DATE` tag when that carries an offset and is not the file's build time, before falling back to `recordedAtLocal`.
- Retention counts a meeting's age from `recordedAtUtc` when it has one, then `recordedAtLocal`, then `createdAtUtc`; storage usage dates meetings the same way. Meetings whose age was already fixed keep it.
- Talk recordings no longer write `recordedAtLocal`. The recorder never knew the room's time zone, so the value was UTC digits presented as local time.
