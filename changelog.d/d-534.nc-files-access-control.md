### Added
- **Opt-in per-participant access control for recordings.** With `CASSINI_NC_ACCESS_CONTROL=true` (off by default in production), the operator freezes each recording's audience to the Talk room's participants at publish time — it grants read-only Nextcloud advanced-ACL (`nc:acl-list`) to each local participant (users, groups, circles) on the meeting's `.opus`; guests, email and federated participants are skipped. The in-Nextcloud viewer is then served **per caller**: the meeting list is built directly from `catalog.json`, filtered to the `.opus` files visible in the caller's own Nextcloud scan, and each recording is fetched as the caller so Nextcloud enforces access — a recording a user is not granted never appears and cannot be played. The read path fails closed (an empty list, never the full archive) on any error. Access is editable afterwards through Nextcloud's own sharing/ACL tools. Enabling it requires the Team folders and Everyone Group apps; Cassini provisions their recording folder + ACL topology automatically — see `docs/exapp-nextcloud-recordings-permissions.md`. With the flag off, behavior is unchanged (the public first pass). A dedicated `cassini` service account owns the recordings and manages their ACLs; privileged setup is performed separately as a Nextcloud administrator.
- The local installed-ExApp harness now declares and passes the access-control deploy variable automatically. `cassini dev stack` exposes `--nc-access-control=true|false`, honors `CASSINI_NC_ACCESS_CONTROL`, shows the resolved value in `stack plan`, and defaults it to `true` for local access-control testing.
