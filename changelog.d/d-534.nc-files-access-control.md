### Added
- **Opt-in per-participant access control for recordings.** With `CASSINI_NC_ACCESS_CONTROL=true` (off by default), the operator freezes each recording's audience to the Talk room's participants at publish time — it grants read-only Nextcloud advanced-ACL (`nc:acl-list`) to each local participant (users, groups, circles) on the meeting's `.opus` and a co-uploaded `<id>.manifest.json` sidecar; guests, email and federated participants are skipped. The in-Nextcloud viewer is then served **per caller**: the meeting list is filtered to what the caller may read (their own Nextcloud scan), and each recording is fetched as the caller so Nextcloud enforces access — a recording a user is not granted never appears and cannot be played. The read path fails closed (an empty list, never the full archive) on any error. Access is editable afterwards through Nextcloud's own sharing/ACL tools. Enabling it requires a one-time Group folders + ACL setup — see `docs/exapp-nextcloud-recordings-permissions.md`. With the flag off, behavior is unchanged (the public first pass). The interim owner/ACL-manager is the Nextcloud admin; a dedicated service account follows.
