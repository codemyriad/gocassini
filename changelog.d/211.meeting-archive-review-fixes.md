### Fixed
- Meeting archive: the `cp --reflink=always` preflight probe cloned from `mktemp -d` (i.e. `/tmp`, a tmpfs on george) into the archive on btrfs. `FICLONE` is `EXDEV` across filesystems and unimplemented on tmpfs, so the probe could only fail — every `--apply` run, the one-time backfill included, would have died in preflight claiming the archive could not reflink and pointing the operator at `ALLOW_FULL_COPY=1`, the switch that turns the whole 123.6 GiB backfill into a real copy. The probe now clones from a file inside the archive root.
- Meeting archive: 45 of the 77 imported `.meeting` bundles carry `source_path=/recordings/<dir>/recording.mkv`, a path *into* a cron bundle. Resolution used `basename`, which for those is the literal string `recording.mkv` and matches nothing, so all 45 would have landed in `unattributed/derived/` and made every run — including every nightly timer pass — exit 5 forever from the first sync onwards. The container path is now mapped onto the first component under the era root, which is the entry that was actually ingested.
- Meeting archive: `refresh_manifest` ran `find derived` unconditionally, which exits 1 when the bundle has no `derived/` — under `set -o pipefail` that killed the run mid-attach, after `MANIFEST.sha256` had been rewritten but before `meeting.json`, `index.jsonl` or `health.json` existed. Every one of the seven real `.mjr` attaches to exactly such a bundle.
- Meeting archive: `MIN_RUN_INTERVAL` applied to every `--apply` run, so the documented two-command backfill had its second command silently debounced — 43 ExApp captures skipped with a green exit 0. The debounce is now the opt-in `--debounce` flag that only `cassini-archive-sync.service` passes, and the runbook is a single invocation carrying both flags.
- Meeting archive: the per-era acceptance counts (88 cron / 15 legacy / 50 hpb / 43 exapp) were only asserted when backfill and sync ran in one invocation, which the runbook never told anyone to do. Each pass now asserts the eras it touched — exactly for the three frozen corpora, as a floor for the growing ExApp one.
- Meeting archive: a `--backfill-old` pass over a source root that exists but is empty — what an unmounted `/mnt/data` looks like — archived nothing and reported `status: ok` with no failed assertions. It is now a preflight failure.
- Meeting archive: attaching a derived bundle committed the component and refreshed the manifest afterwards; a crash in between left the component on disk and unrecorded, and the existence latch made that permanent while `sha256sum -c` (which only checks the files it lists) kept passing. A component that is present but absent from `MANIFEST.sha256`/`meeting.json` is now detected and repaired.
- Meeting archive: `meeting.json` and every other archive file are written to a temp file and renamed into place instead of being truncated and rewritten, and an unreadable `ARCHIVE/meeting.json` now fails the run by name instead of silently dropping the meeting from `index.jsonl` and `INVENTORY.md`. The healthcheck's A6 assertion checks that every `meeting.json` parses and gives the matching remediation.
- Meeting archive: a quarantined source (unidentifiable bundle, symlinked tree, failed byte conservation, archive-name collision) set `last_run_status: degraded` but still exited 0, so systemd saw success and no alarm was raised. A degraded run now exits 5.
- Meeting archive: `${#ARRAY[@]}` on a never-assigned `declare -A` is a fatal unbound variable under `set -u`, so an empty operator DB or a `current/` with no `.meeting` bundles aborted the pass with a bash internal error before the reverse reconciliation could report the deletion that caused it.
- Meeting archive: the source fingerprint hashed the mtime as `%y`, rendered in the caller's timezone, so a run under a different `TZ` reported every already-ingested source as `source-mutated`. It now hashes epoch seconds.
- Meeting archive: `truncate_second` appended a second `Z` to a whole-second RFC3339 stamp (`…:24Z` → `…:24ZZ`), which reached `anchor_utc`, `ended_at_utc`, `key` and the directory name; and job-only rows derived `date_local` from the UTC date while every meeting row uses the local one, putting a job that finished after 22:00 UTC in the wrong `by-date/` bucket.
- Meeting archive: `ReadWritePaths=` entries pointing into the ExApp docker volume made a missing directory a unit *start* failure (226/NAMESPACE). An ExApp reinstall would therefore have failed the ingest unit **and** its `OnFailure=` alert handler, silencing the entire alarm chain. The alert handler's paths are now all optional and its marker directory is a `StateDirectory`.
- Meeting archive: a dry run resolved derived bundles and `.mjr` files only against committed directories, so the very first `--dry-run` — the plan an operator is told to review before authorising 123.6 GiB — raised about ten alarms about its own dry-ness and exited 5. Planned captures now count.
- Meeting archive docs: the backfill runbook, the acceptance-assertion claims, the `ops/systemd/` install paths (that directory does not exist), the `cassini-archive-watchdog` unit name, and the `MAX_QUIET_WEEKDAYS=3` calibration claim ("fires exactly once over the corpus" — replayed against the real calendar it fires twice) were all wrong and are corrected.
