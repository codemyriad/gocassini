### Added
- Each AI provider now carries a default model, set in AI providers. Summaries and insights use it unless the step names its own, and the Prepare panel shows which model an insight will run on instead of offering a second place to choose one.
- A failed insight can be retried from its card in the browse list and from its document, not only from the panel that started it. The failure copy says what went wrong in plain words.

### Changed
- Generating an insight closes the Prepare panel and puts the new run at the top of the browse list, where it updates like every other insight.
- The selection is bounded to the operator's 20-meeting cap before a request is made, with a sentence saying how many to unpick.

### Fixed
- An insight run always asks the chosen provider for that provider's model; it can no longer inherit the summary step's model on a different endpoint.
- When the AI endpoints or a model list cannot be read, the app now shows the operator's own error instead of a generic HTTP status. A provider base URL ending in `/chat/completions` or `/models` is refused with a hint to give the API root.
- A non-admin's "No AI endpoint" card in the Prepare panel refreshes each time the panel opens, once an administrator has configured one.
