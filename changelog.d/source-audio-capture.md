### Added
- Source-side audio capture, first stage: while Talk's official recording is active, a participant's browser can now record its own microphone before Opus encoding and before the network, then upload as soon as Talk confirms recording stopped. A small same-version `cassini_capture` companion app loads the opt-in payload on authenticated Talk calls through Nextcloud's public additional-scripts event; it does not intercept or rewrite Talk's bundle. Reloading during a recording resumes from Talk's room state, retries the durable pre-reload prefix, and limits an abrupt-navigation gap to a two-second checkpoint; leaving remains a stop/upload fallback. Cassini's recorder subscribes through the SFU, so until now the transcript could only ever be as good as each participant's uplink — words lost to packet loss were simply gone. The build can optionally transcribe a speaker from that audio instead of from what survived their uplink; ingestion is off unless an administrator sets CASSINI_SOURCE_AUDIO_INGEST, and a capture is only used when it comes from the same room and an overlapping call. Placement takes its rate from the participant's own encoded-frame timestamps — immune to packet loss, because those describe frames the client encoded rather than packets that arrived — and its offset from a wall-clock anchor the recorder now records per track. Offset accuracy is therefore bounded by how well the participant's clock agrees with the server's; a placement that falls outside the recording is refused, and every other failure leaves that speaker on the recorded track. Capture is off unless a user explicitly opts in, records the track Talk is sending (so Talk's own mute is honoured at the source and cannot be bypassed), and every upload is filed under the AppAPI-authenticated caller and refused for a room they were not in. The published audio stays the recorded mix — that is the meeting as everyone in the room heard it — and manifest.provenance.sourceAudio records which speakers were transcribed from their own capture and how well it fitted. Ingestion is also contained so it can never cost a meeting: the decode of participant-supplied media is bounded by a deadline and cancelled with the build, a WAV that cannot be written says so instead of being handed on as if it were whole, and a capture set aside while a re-upload is promoted is no longer discovered as a second capture for the same speaker. A client whose upload is refused for good now discards it rather than re-uploading a meeting-sized body on every Talk page load. A capture cut into more than one segment — which happens whenever a participant changes microphone during a recorded call — was refused by the server and never stored, because Nextcloud's AppAPI proxy rebuilds the upload through PHP and PHP keeps only the last file sent under a repeated field name; segments are now identified by their file name, which survives that hop. Disabling the app now really does turn collection off: the switch is written back to Nextcloud before the app answers the lifecycle call, instead of in a goroutine racing the container's own shutdown, which previously left the stored value saying enabled and the companion still injecting the capture payload into Talk call pages. A capture is now refused when it does not cover the call it came from. Substitution is whole-track, so a capture that succeeds while holding only part of a call turned the rest into silence with the recorded track suppressed underneath it, deleting speech the recorder had heard perfectly well; the manifest records how much of its call each capture covered, either way.
