### Added
- An insight now appears in the browse list beside the meetings it was drawn from, and under every room those meetings came from: a question asked of three rooms is found in all three, not filed under one of them. A Meetings/Insights switch above the list narrows to one kind or the other, and the last kind showing cannot be switched off. Insights that are queued or still running are listed too, saying so — an answer that takes minutes is visible while it is being written rather than appearing from nowhere afterwards — and a listing that fails says it failed instead of reading as "there are none".
- Opening an insight shows the question it was asked, the meetings it read — each of which opens as itself, with the way back to the insight — the answer, and who ran it with which workflow and version. Every source meeting lists the insights that read it, so the link works in both directions. A meeting or an insight you may not read is simply absent from both, with nothing anywhere saying that it existed. The standalone viewer export, which has no operator behind it to have run anything, shows none of this and offers no filter for it.
