### Added
- Operator › Settings › Webhooks: set up the event receiver, see the last seven days of delivery, and send a signed `webhook.test` event (`POST operator/settings/webhook/test`). `GET`/`PUT operator/settings/webhook` now return the event `catalog` and a `delivery` summary, and refusals carry an `error_code`. See `docs/events.md`.

### Changed
- Webhook `events` is now required with a receiver (no more "empty means all"), and the timeout is `timeout_seconds` (1 to 60) instead of a `timeout` duration. 0.4.0 settings are converted on upgrade.
- A queued webhook event is only sent to the address it was queued for; changing or removing the receiver, or unticking an event, deletes its waiting events.
- A webhook receiver that is down is backed off as a whole, and `Retry-After` on a `429` or `503` is honoured.

### Security
- A new webhook address needs a new secret, and a secret set through the API must be at least 32 characters. Turning delivery off deletes the stored secret and events.
- The webhook outbox keeps an event's payload only while the event waits, 24 hours at most.
- Webhook requests are never sent to link-local or cloud-metadata addresses.
