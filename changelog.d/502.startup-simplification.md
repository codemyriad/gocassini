### Added
- Support bundles now say whether Cassini's data is on storage that does not survive the container (data_on_ephemeral_storage in configuration.json). The value is safe in a scrubbed bundle.
- The start-up log now says when settings.json or llm-settings.json was not found, so a support bundle shows that settings started from defaults.

### Changed
- The setup notice no longer tells administrators to disable and enable the app; Try again on the notice runs the same check.
- The setup notice no longer says recordings will fail. It now says new recordings may not be saved until the problem is fixed, or that Cassini checks again before it saves one.
- Cassini reads settings.json and llm-settings.json once, at start. Opening Settings or AI providers no longer reads or writes either file, so a hand edit of these files needs a restart.
- settings.json is now created by the first save in Settings, not when Cassini starts.
- The startup lines that explain a reset, such as a new Talk recording secret or a missing settings file, are now kept in the support journal, so support bundles include them.
- When Cassini generates a new Talk recording secret, the log now says to press Connect Talk again if Talk already used Cassini for recording.
- The warning for data on temporary storage is now logged once, by the operator, instead of also by the container start script. It now also checks the work root. It names the cause: data on the container layer is lost when the container is recreated or the app is updated; data on tmpfs is lost at every container stop and host reboot.
- Every small state file next to jobs.sqlite3 (settings.json, llm-settings.json, talk-provisioning.json, recording-setup.json, the retention and event webhook settings) is now saved the same way: through its own temporary file, then synced to disk together with its folder. A leftover temporary file can no longer block a save, and a save is less likely to be lost by a power cut right after it.
- The Connect Talk panel now tells Nextcloud All-in-One administrators to turn off AIO's Talk Recording-server and set NEXTCLOUD_KEEP_DISABLED_APPS=true; otherwise AIO removes Talk's recording backend every time Nextcloud starts.
- When Talk refuses Cassini, the check now adds that a refusal after every Nextcloud restart, update or backup means something in Nextcloud's startup resets Talk's recording backend, as Nextcloud All-in-One does by default.
- The install guide's storage section now treats the whole AppAPI volume as one unit to back up and restore, and says what survives a container restart, a recreate and a host reboot.

### Removed
- The recording setup guide no longer describes the Connect Talk command generator, the administrator request and the backup file it made. They were removed before 0.2.0. Rollback now points to the install guide.
- Cassini no longer writes app-state.json. Nothing read it. An existing file is left alone and can be deleted; backup scripts should treat it as optional.

### Fixed
- A host reboot no longer marks installed transcription models as not ready. A model is checked again after an upgrade or a GPU driver change, not after every reboot.
- A Nextcloud that is busy or still starting no longer makes Cassini refuse recordings. Only a definite answer, such as a missing recordings account or a disabled share API, refuses them. A server error, a rate limit or a timeout now gives a "degraded" state, and the next publish checks again. If the share API keeps failing, a call is still recorded; its publish then fails, keeps the local media, and can be run again.
- When Cassini starts before Nextcloud answers, for example after a server reboot, the "needs an administrator" banner now clears by itself within about five minutes of Nextcloud answering.
- Cassini checks Nextcloud storage once at start, not twice.
- The check at start no longer forgets the saved Talk test room when Talk answers "not found" for a moment. Only an administrator's Check again can forget it.
- A hardware change at start, such as a GPU that appears late or a different CPU count, no longer rewrites settings.json or drops a pinned device. A pinned GPU that is missing at start is ignored until the next start; the saved pin is kept.
- A settings file that loads correctly is no longer replaced by defaults when Cassini cannot write to its folder at start.
- Opening Settings while settings.json or llm-settings.json is missing no longer writes defaults over the running settings.
- When settings.json or llm-settings.json cannot be loaded at start, Cassini keeps the file as settings.json.rejected-N (or llm-settings.json.rejected-N) before a save can replace it, and the log says how to restore it.
- While settings.json cannot be loaded, new recordings are shared with attendees only, not with the whole room. A fresh install still shares with the room by default.
- Enabling the app or its first-time setup in AppAPI can no longer fail with an error because app-state.json is damaged or the volume is full.
- Saving retention settings no longer reports an error for a change that was already saved, when only the folder sync failed.
- Cassini commands run inside the AppAPI container with docker exec, such as cassini models import, now use the operator's model store on the persistent volume, not a folder inside the image.
