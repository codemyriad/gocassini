### Added
- **Automatic setup of the recordings directory and its permissions.** When per-participant access control is enabled (`CASSINI_NC_ACCESS_CONTROL=true`), enabling the Cassini ExApp now provisions everything the model needs by itself, over Nextcloud's HTTP APIs — no manual `occ` group-folder setup. On the enabled edge the operator creates the `Cassini` Group folder with its default-deny advanced-ACL floor, assigns the viewer group read and the owner full permissions, delegates the owner as ACL manager, applies the root container ACL (so the owner can write and every logged-in user can traverse), creates the canonical `Cassini/Recordings/meetings` collections, and reconciles every account into the `recording-viewers` group (with a periodic sweep so new accounts converge). The result: everyone with a logged-in account can read/browse the recordings directory, while each recording file stays restricted to the meeting's participants via the per-file ACLs applied at publish. Every step is idempotent and best-effort. The one remaining prerequisite is the Group folders ("Team folders") app being enabled, which an ExApp cannot install for itself; the local harness now enables it automatically in `bootstrap.sh`.
