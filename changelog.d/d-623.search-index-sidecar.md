### Added
- You can now search across your meetings. Cassini indexes each transcript as it is published and answers `published/search` with the moments that match — the meeting, the speaker, and where in the recording they said it. You only ever see meetings you can already open.
- Search knows the names transcription gets wrong. Looking for "cassini" also finds the recordings where it was written down as "casino", and each result says whether it matched your words or a known mis-hearing of them.
- Every answer says how much it covered: how many of the meetings you can read were actually searched. A meeting Cassini could not index is reported as outside coverage rather than passing for one with no matches, and an unreachable archive is an error rather than an empty result.
- Cassini's search index lives in its own `search.sqlite3` file beside the job database and holds nothing that cannot be rebuilt from the published recordings. Deleting it is safe: it costs a rebuild and never touches recordings or job history.
- `cassini-operator backfill-search` indexes meetings published before the index existed. It is safe to re-run and safe to interrupt, and it indexes a meeting only when the stored transcript matches the recording that was delivered.

### Security
- Search results never carry transcript text, and the search index cannot return the words it indexed. A search query is kept out of the operator's request log, where it would otherwise sit indefinitely.
