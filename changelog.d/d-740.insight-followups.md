### Fixed
- A summary or insight the model stopped writing at its output limit is no longer recorded as a success. The run fails and says the answer was cut off at the model's output limit, so a half-written document is never published as a whole one.
- The AI endpoint picker now works on a plain compose deployment too: the `/ai/providers` routes were mounted only under the ExApp base path, so the Prepare panel's provider list 404ed there.
- Two insight runs can no longer run at once on one request: a retry whose row had been failed by the stale-run sweep and retried again used to start beside the newer attempt.
- An insight stopped by an operator restart now says so and asks you to retry it, instead of claiming it took longer than an hour.
- A finished insight whose outcome could not be written down is retried a few times before giving up, and if it still fails the log names the delivered document so it can be found.
- A succeeded insight whose document you have since moved or deleted now says where it was, rather than "its document is empty".
- Meeting-context refusals are never cached by the app proxy, and a meeting list that could not be read answers "unavailable" rather than "not one of yours".

### Changed
- The endpoint's address stays with administrators. The insight document's provenance records the model and endpoint kind but no longer its base URL; an unnamed endpoint is shown as "Endpoint 1" rather than by its host; and a model list that cannot be fetched is reported to non-administrators without the URL.
- Registering your first endpoint switches summarising on exactly once in a deployment's life. Removing every endpoint and adding one back no longer switches it on again for an administrator who had turned it off.
- Removing an AI endpoint asks for confirmation first, naming the endpoint, that its stored key is destroyed, and which steps stop running on it.
