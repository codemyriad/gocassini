### Added
- The **Participant and project vocabulary** setting now guides the transcriber itself. Terms are applied as sherpa-onnx contextual biasing, so the recogniser can write "Librocco" or "Aire Spaces" where it used to invent a spelling. A term is only ever emitted where the audio already supports it, so the vocabulary corrects spellings without putting words in anyone's mouth.
- `provenance.speechToText.hints` in the build manifest records how many terms were used, the boost, and the decoding method. When a vocabulary is configured but cannot be applied, it records that and why, so a build that ignored the setting never looks like one that honoured it.
- `CASSINI_STT_HINTS_DISABLED` turns biasing off while keeping the vocabulary; `CASSINI_STT_HINTS_SCORE` overrides the boost.

### Changed
- **Transcription output changes for every meeting, not only for the listed terms.** Hotwords are only read under modified beam search, so the balanced and best quality tiers now decode with beam search instead of greedy search. It is a different decoder and it decides differently on marginal audio: measured on real meeting audio it lost a sentence on one clip and gained words on another. Decode cost is 1.3x to 1.5x, still far faster than realtime (worst measured realtime factor 0.091, so an hour of meeting decodes in about five and a half minutes on CPU). Memory is unchanged.
- The fast quality tier is unaffected. It runs a CTC model, which sherpa-onnx cannot bias, so it keeps greedy search and records the vocabulary as not applied rather than ignoring it silently.
- The vocabulary previously steered the LLM cleanup prompt and explicitly did not affect the transcript. It now affects the transcript and nothing else.
- Decoder hints need a model bundle that ships `bpe.vocab`. Bundles without one record the vocabulary as not applied, and say so, rather than decoding unbiased in silence.
