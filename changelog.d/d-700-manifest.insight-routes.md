### Added
- Insights are reachable from the browser: the manifest declares three new USER routes — `insights` (create a run, list your own), `insights/<id>` (read one with its document) and `insights/<id>/retry`. They are the first routes in Cassini a logged-in non-administrator may POST to, and they are USER rather than ADMIN because a run acts only within what that person could already do by hand: it reads the meetings they picked, as them, and writes the answer into their own Nextcloud Files. **On upgrade** an existing install picks the new routes up from the release itself — no re-registration needed, because every release bumps `<version>` (see below).

### Changed
- `docs/exapp-update-constraints.md` answers the question it used to flag as unverified: an in-place `app_api:app:update` **does** rewrite AppAPI's route allowlist, but only when the manifest it is handed carries a new `<version>` — with the same version it short-circuits on "already updated" and the allowlist is untouched. Routes therefore behave unlike deploy environment variables, which stay creation-time. The rule for release review is that a release changing `<routes>` must bump `<version>`, which `scripts/bump-exapp-version.sh` already does. The measurement is written up with its evidence and is re-runnable as `harness/bin/check-route-refresh.sh`.
- The privacy note now covers insights: a question sends the picked meetings' transcript and summary text to the configured LLM endpoint, the call uses the **instance's** API key — so the request reaches your provider attributable to the deployment, not to the person who asked — and the answer is written into that person's own Nextcloud Files, never beside the recordings.
