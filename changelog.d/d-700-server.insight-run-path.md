### Added
- An insight you ask for in the app is answered by the deployment on your behalf and delivered into your own Nextcloud Files, under a **Cassini Insights** folder in your home. You own the file outright, so Nextcloud's own sharing works on it and nothing new decides who may read it. It is deliberately not filed under `Cassini/` — that name is the shared recordings Team folder, which is read-only for everybody but Cassini's service account — and an insight is never written next to the recordings.
- A document is never overwritten. Each file is named for the day, the template and the run it came from, and if something is already at that name the run writes the next free one and records which it used.
- Every meeting an insight covers is fetched **as you**, over WebDAV, at the moment the run happens — so Nextcloud's own per-file permissions decide what is in the bundle, and a run can only ever be assembled out of meetings you could already open yourself. A retry re-checks that: a meeting you can no longer read stops the run rather than quietly dropping out of the answer.
- A failed run says which of the five things went wrong in words that name the fix — no endpoint configured, the endpoint refused the request, the model did not answer, the answer could not be written, or the request itself — rather than reporting one general failure.

### Changed
- The subprocesses an insight runs no longer inherit the operator's own credentials. The AppAPI shared secret, the Talk recording and signaling secrets and the operator API token are removed from their environment: none of them is read by any `cassini` command, and the AppAPI secret in particular is what lets a process act as any account on the instance. The step that only assembles the meetings loses the LLM credentials as well, since it never calls a model.
- An insight is bounded in the three ways that can run away: how many meetings one may cover, how long one attempt may take before it is stopped, and how large the answer may be. Each limit is a refusal that says so, never a silently shortened document, and only two runs are performed at a time — the rest wait, and say they are queued.
