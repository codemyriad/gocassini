### Changed
- **Transcription runs on the CPU when the host has no GPU.** Operator builds
  resolve their device per run — CUDA when the image carries the CUDA runtime and
  an NVIDIA device is visible, CPU otherwise — instead of blocking every build on
  a GPU-less install. Recordings already stuck in `build/blocked` recover with
  **Rerun** in Cassini Admin; no image or deploy-daemon change is needed.
- Each image carries the model of the tier it runs by default, and any other
  tier downloads once into a model cache on the persistent volume. The portable
  image bakes the 0.6B int8 model, the GPU image bakes fp32, and both stay small.
  A download survives a container recreate, and a host with no network egress
  gets a clear error that names the missing model.

### Added
- Cassini Admin's Transcription quality panel reports the device and model the
  next build will actually use, so a CPU run is stated up front rather than
  inferred from a failed build. The device override adds a **CPU** choice
  alongside Auto and CUDA.

### Removed
- The **Model override** field. It accepted only the three models the quality
  tiers already select, so it duplicated the tier control with no
  discoverability — and pinning an int8 model alongside CUDA produced a run that
  fragmented back onto the host CPU while reporting a GPU. Quality and device are
  now the whole of the policy. A `model_override` left in an existing
  `settings.json` is ignored.

### Fixed
- Selecting **Fast** now works on a CPU host. The pre-build environment check
  demanded transducer model files of every non-fp32 model, so the 110M CTC
  model — which ships a single `model.int8.onnx` — failed validation although it
  was bundled and correct.
- An int8 model can no longer be pinned alongside CUDA. Those graphs fragment
  back onto the host CPU under the CUDA execution provider, so the combination
  reported a GPU run while doing something else; it is now refused when saved
  and when a build is admitted.
- A stored `device_override=cpu` is preserved instead of being erased on every
  operator restart. Pinning `cuda` on a host without a usable GPU still blocks
  the build with an actionable message rather than silently using the CPU.
