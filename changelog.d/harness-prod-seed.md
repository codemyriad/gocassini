### Added
- `cassini dev meetings pull --out <dir>` mirrors the meetings a Nextcloud account may read into a local seed pack — `catalog.json` plus `meetings/<id>.opus`, the shape a published site has always had. It pulls everything by default, `--limit` keeps the newest N, and `--room`/`--from`/`--to` narrow it the way `cassini meetings list` does. `--dry-run` reports the total size before committing to the transfer, and re-running skips what is already on disk at the size the server reports, so an interrupted pull is resumed by repeating the command. Every request is a GET or a HEAD; nothing is written back.
- `cassini dev stack up --seed <dir>` loads a seed pack into the harness, and `harness/bin/seed-nc-files.sh --pack <dir>` does the same against a stack that is already running. A local development stack can now be brought up holding a real archive instead of a synthetic fixture, which is what the meeting list, cross-meeting search and insights actually need to be worked on. Seeding is a filesystem copy plus `occ groupfolders:scan` rather than a WebDAV upload, so 2 GB of recordings are copied and scanned in about four seconds, followed by a permissions pass of roughly half a second per meeting. The catalog is merged rather than replaced, so meetings a stack recorded itself survive a seed.
- Seeded meetings are given an explicit read grant, and are therefore readable by every account on the stack, which the seeder says on every run: production's per-meeting permissions name production accounts and do not travel with the data. They also carry no operator job history. Neither affects the published surfaces, and both are stated so that no access-control change is tested against a seeded archive.
