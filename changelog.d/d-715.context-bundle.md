### Added
- `cassini meetings context` takes several meeting ids and prints one document holding all of them, so a question can be asked of a set of meetings rather than one at a time. The meetings appear in the order you named them, separated by a `---` rule, and the `--json` form carries them as a `meetings` array whose every entry is exactly the single-meeting document the command has always produced. An id you cannot read — or one that does not exist, which is answered the same way on purpose — fails the whole run: a bundle that quietly dropped a meeting would answer a question asked of all of them using only some of them, and look right doing it.
- `cassini meetings context --timestamps` cites each passage's start time, as `MM:SS` or `H:MM:SS` past an hour, beside the speaker. Off by default. The timings were already in the `--json` output and had no way of reaching the text an agent actually reads, so nothing asked to say *where* something was said could point at it.
- The context bundle's format has a published schema, `spec/cassini-meetings-context-v1.schema.json`, and its output is pinned by fixtures. `cassini.meetings.context.v1` was a version string with nothing written down behind it; now a change to what the command emits shows up as a diff in a checked-in file.

### Changed
- `cassini meetings context` fetches the recording catalog once per run instead of once per meeting, so every meeting in a bundle is resolved against a single view of what you are allowed to read.
- `--keep-opus` is refused when more than one meeting is asked for, and so is the same meeting id given twice. Both used to be silently meaningless; one file cannot hold several recordings, and the same transcript twice spends the context budget on one meeting while reading as coverage of two.
