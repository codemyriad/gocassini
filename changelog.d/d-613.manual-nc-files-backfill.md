### Changed
- **Enabling or updating the app no longer re-uploads your whole recording archive.** It used to copy every recording it had ever published into Nextcloud Files again on each enable, install and update, under a fixed time budget for the entire batch. Past a certain archive size that ran out of time before it could update the recording list — and because the list is written last, it stayed frozen at its previous contents permanently, with new recordings delivered but invisible and nothing said about it. Recordings have gone straight into Nextcloud Files as part of publishing for some time now, so nothing depended on this any more.

### Added
- **A one-shot migration for recordings published by an older version.** Recordings made before Cassini stored them in Nextcloud Files live only on the app's own storage, and nothing publishes them again. `./scripts/backfill-nc-files.sh` moves them across, run once by hand after updating; `--dry-run` reports what it would move without changing anything. Migrated recordings are readable only by the Cassini service account, because the audience a recording had when it was published cannot be recovered afterwards — grant access from the Files app, or use `--public` to make them readable by every signed-in account as they were before Cassini had access control. The migration refuses to run when Nextcloud Files already holds recordings, so it is safe to run when you are unsure whether it is needed, and skipping it entirely is a supported choice: the old recordings simply stay where they are and everything published from now on works normally.
