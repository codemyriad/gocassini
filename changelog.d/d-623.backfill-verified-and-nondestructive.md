### Fixed
- `cassini-operator backfill-search` now verifies a local transcript against the checksum the archive itself records for the delivered recording, instead of a digest from the job database that could never disagree with the local copy. A meeting whose local transcript belongs to a re-run that never published is detected and indexed from the published recording instead, so search only ever cites words that are in a recording you can play.
- A read failure during `backfill-search` — a timeout, a busy Nextcloud — no longer removes a meeting's existing search entries. It is reported as failed and re-running is the fix; entries only change on evidence about the recording itself.
- `backfill-search` no longer reads the job database at all, so it can run while the operator is publishing; the old database-is-locked failure is gone. Where the delivery recorded a checksum, a re-run now confirms an unchanged meeting with one metadata query instead of re-downloading the recording.
