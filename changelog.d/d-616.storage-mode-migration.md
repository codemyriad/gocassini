### Changed
- **The two storage modes no longer share a folder.** Recordings in the default mode now live in the `cassini` account's own `CassiniNoACL/Recordings`; the access-controlled mode keeps its `Cassini` Team folder exactly as it is. They used to share one path, and because a mounted Team folder wins that path — Nextcloud physically renames the colliding directory out of the way — every switch between the modes had to be a move, with the archive discovered by pattern-matching a name the server chose. Existing installations are carried across automatically the next time Cassini is enabled, from whichever of the three places the old layout could leave them; an access-controlled installation moves nothing.
- **Switching storage modes is now a copy, and can be re-run.** Cassini copies the archive into the new mode's folder, checks every recording arrived, records the new mode, and only then empties the old folder. Whichever mode `storage_settings.json` names, that folder holds a complete archive — so a switch interrupted by a restart, a timeout or a closed browser tab leaves nothing stranded and can simply be asked for again.

### Added
- **A way out of a switch that did not finish.** `storage_settings.json` carries a `migration_clean` flag, and when it is false the Setup tab says which folder still holds a leftover copy and offers one button to clear it. Asking for the mode that is already in force used to be a no-op, which made this state impossible to fix from the app at all. The cleanup refuses to remove anything that is not already in the folder the current mode reads.
- The Setup tab now says when recordings are sitting in the mode that is *not* in force — the state where an archive looks like it has vanished, when in fact a switch was never made.

### Fixed
- **Switching from access-controlled back to the default mode no longer fails on password confirmation.** It used to unmap the Team folder's groups, which is a write Nextcloud refuses to an external app on 33.0.6–33.0.7 and 34.0.1 onwards. Nothing needs it now: the Team folder is emptied and left in place, which also makes switching back immediate.
- **The confirmation dialog said "there are no published recordings to move" on an instance with recordings to move.** It looked for the archive in the two places a half-finished switch could have left it and not in the place it normally is, so an ordinary default-mode installation previewed as empty and then moved everything. It also now distinguishes an empty archive from one it could not read, rather than reporting both as nothing.
- **A finished setup no longer leaves a stale "Cassini is not configured" warning.** The app read that verdict once when the page opened and never again, so building the substrate on the Setup tab left every other tab showing the problem it had just fixed, until the browser was refreshed by hand. It re-reads it as soon as something changes, without reloading the page — so nothing else you had open is thrown away.
- A default-mode installation no longer serves an empty archive after a container restart. Reading was gated on a check that has stopped being relevant now that the two modes have separate folders.
