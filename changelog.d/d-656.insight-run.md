### Added
- `cassini insight run` asks one question of several meetings and writes the answer. It reads the context bundles `cassini meetings context --json --out` produces — one `--context` per bundle, in the order you name them — runs the summarise workflow over all of them at once, and writes the result to `--out` or to standard output. `--model` overrides the model for that run alone, and `--timestamps` shows the model where in each meeting something was said so it can cite it.
- The document it writes carries its own provenance as frontmatter: which meetings it was produced from, with their rooms; the workflow's id, version and the content hash of the exact prompt bytes that produced it; the endpoint and model that answered; and when. A summary has always been able to say only that some model wrote it at some point, which is not enough to tell two documents from different prompt versions apart. `--record` writes the same record as JSON beside the document, so a grading harness reads one pair rather than parsing prose.
- `cassini insight run` exits with a different code per outcome — no endpoint configured, the endpoint refused, the model failed or timed out, a bad request — instead of warning and carrying on. Skipping quietly is reasonable for a summary nobody asked for and never for a document somebody did. The codes are listed in `cassini insight run --help`. A failed run still writes its `--record` file, saying what was attempted and why it did not happen.
