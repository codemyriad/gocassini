# G3 — Meeting summary

> Every recorded meeting carries a concise, human-readable summary — generated by the pipeline and displayed in the viewer.

- **Project:** [P1 — Cassini internal MVP](P1-cassini-internal-mvp.md) · **Phase:** PHASE-1 · **Requirements:** R5
- **Status:** ✅ Complete
- **Last updated:** 2026-06-23

## What this goal is

G3 delivers the meeting-summary feature end to end: a shared summary contract (a six-section markdown template), LLM-driven generation of that summary inside the core pipeline, and display of the rendered summary in the viewer. It satisfies R5 — each meeting artifact includes one minimal summary.

The work split into three concerns that meet at a single committed template: the contract/template plus hosted demo data, the viewer-side rendering, and the pipeline-side generation. Because all three were built against the same template, the viewer "just works" against both curated demo data and freshly generated output.

## Why it matters

A recording is far more useful paired with a skimmable summary of what happened. R5 makes this a baseline MVP capability, and the contract-first split let display and generation proceed in parallel without integration friction.

## Definition of done

- A committed summary markdown template defines the contract (six sections), shared by renderer and generator.
- Curated demo data is hosted and pullable, so the viewer can be exercised before generation exists.
- The viewer renders the summary as markdown, with graceful fallback when none is present.
- The core pipeline generates the summary via an LLM as a sidecar markdown file; generation is optional/configurable.
